Cours : Les collections en Java

1. Introduction aux collections

Les collections en Java sont des structures de données dynamiques permettant de stocker, manipuler et parcourir des groupes d’objets. La bibliothèque Java Collections Framework (JCF) fournit des interfaces, classes et algorithmes pour travailler avec ces structures de manière efficace.

Elles remplacent les tableaux dans de nombreux cas grâce à leur flexibilité et leurs fonctionnalités riches.

1.1 Interfaces principales

  • Collection : L’interface de base pour toutes les collections.
  • List : Une collection ordonnée qui permet les doublons (ex. : ArrayList, LinkedList).
  • Set : Une collection non ordonnée sans doublons (ex. : HashSet, TreeSet).
  • Queue : Une collection pour les files d'attente, souvent ordonnée par priorité (ex. : PriorityQueue).
  • Map : Une collection de paires clé-valeur (ex. : HashMap, TreeMap).

1.2 Pourquoi utiliser les collections ?

  • Les collections permettent de stocker des objets dynamiquement sans définir de taille fixe.
  • Elles offrent des fonctionnalités prêtes à l’emploi pour trier, filtrer ou rechercher des données.
  • Elles sont interopérables avec de nombreux frameworks et API Java.
  • Manipuler des groupes de données efficacement grâce à des méthodes prêtes à l’emploi.
  • Éviter la duplication de code grâce à des structures standardisées.

2. Utilisation des collections

2.1 Où les utiliser ?

  • Dans `main` : Pour des programmes simples ou temporaires. Les collections sont déclarées localement et utilisées pour gérer les données dans le contexte limité de cette méthode.
  • Dans une classe dédiée : Pour centraliser la gestion des données (ex. : une liste d’utilisateurs). Utilisé pour des programmes structurés. Les collections sont encapsulées dans une classe, souvent avec des méthodes pour les manipuler.
  • Dans un fichier séparé : Idéal pour les programmes complexes nécessitant une organisation modulaire où plusieurs classes ou fichiers utilisent les mêmes collections. On crée une classe dédiée pour centraliser la logique métier et éviter la duplication.

2.2 Exemples d'utilisation

a. Dans `main`

import java.util.ArrayList;

public class ExempleMain {
    public static void main(String[] args) {
        ArrayList<String> noms = new ArrayList<>();
        noms.add("Alice");
        noms.add("Bob");
        System.out.println(noms);
    }
}

b. Encapsulation dans une classe

import java.util.ArrayList;

public class PersonneManager {
    private ArrayList<String> noms = new ArrayList<>();

    public void ajouterNom(String nom) {
        noms.add(nom);
    }

    public ArrayList<String> getNoms() {
        return noms;
    }
}

public class Main {
    public static void main(String[] args) {
        PersonneManager manager = new PersonneManager();
        manager.ajouterNom("Alice");
        System.out.println(manager.getNoms());
    }
}

c. Dans un fichier séparé :

import java.util.HashMap;

public class ConfigManager {
private static HashMap<String, String> configs = new HashMap<>();

static {
    configs.put("db_url", "jdbc:mysql://localhost");
    configs.put("db_user", "admin");
}

public static String getConfig(String key) {
    return configs.getOrDefault(key, "Clé non trouvée");
}
}

public class Main {
public static void main(String[] args) {
    System.out.println(ConfigManager.getConfig("db_url"));
}
}

3. Comparaison avec les classes

  • Classes : Représentent un type défini par l’utilisateur avec des propriétés et des comportements, aussi défini par l'utilisateur. Par exemple, une classe Person peut contenir des attributs comme `nom` et `âge`, ainsi que des méthodes.
  • Collections : Représentent des groupes d’objets, mais ne définissent pas de comportements spécifiques pour ces objets.

4. Liste principale des collections

4.1 List

Les listes permettent de stocker des éléments dans un ordre précis, avec des doublons autorisés.

  • ArrayList : Une liste basée sur un tableau dynamique. Tableau dynamique rapide pour l'accès aux éléments.
  • LinkedList : Une liste basée sur une structure de liste chaînée. Idéal pour des ajouts/suppressions fréquents.
import java.util.ArrayList;
import java.util.LinkedList;

public class ExempleList {
    public static void main(String[] args) {
        // ArrayList
        ArrayList<String> arrayList = new ArrayList<>();
        arrayList.add("Java");
        arrayList.add("Python");
        arrayList.add("C++");
        System.out.println("ArrayList : " + arrayList);

        // LinkedList
        LinkedList<String> linkedList = new LinkedList<>();
        linkedList.add("Ruby");
        linkedList.add("Go");
        System.out.println("LinkedList : " + linkedList);
    }
}

4.2 Set

Les ensembles ne permettent pas les doublons.

  • HashSet : Un ensemble non ordonné basé sur une table de hachage. Ensemble rapide, non ordonné.
  • TreeSet : Un ensemble trié basé sur un arbre binaire. Ensemble trié.
import java.util.HashSet;
import java.util.TreeSet;

public class ExempleSet {
    public static void main(String[] args) {
        // HashSet
        HashSet<String> hashSet = new HashSet<>();
        hashSet.add("Apple");
        hashSet.add("Banana");
        hashSet.add("Apple"); // Doublon ignoré
        System.out.println("HashSet : " + hashSet);

        // TreeSet
        TreeSet<String> treeSet = new TreeSet<>();
        treeSet.add("Zebra");
        treeSet.add("Lion");
        treeSet.add("Elephant");
        System.out.println("TreeSet : " + treeSet);
    }
}

4.3 Map

Les maps permettent de stocker des paires clé-valeur.

  • HashMap : Une map non ordonnée basée sur une table de hachage. Map rapide, non ordonnée.
  • TreeMap : Une map triée par clé.
import java.util.HashMap;
import java.util.TreeMap;

public class ExempleMap {
    public static void main(String[] args) {
        // HashMap
        HashMap<String, Integer> hashMap = new HashMap<>();
        hashMap.put("Alice", 25);
        hashMap.put("Bob", 30);
        hashMap.put("Alice", 28); // Remplace l'ancienne valeur
        System.out.println("HashMap : " + hashMap);

        // TreeMap
        TreeMap<String, Integer> treeMap = new TreeMap<>();
        treeMap.put("Charlie", 35);
        treeMap.put("Alice", 28);
        System.out.println("TreeMap : " + treeMap);
    }
}

4.4 Méthodes utiles

  • add(), remove(), contains() : Pour ajouter, supprimer ou vérifier un élément.
  • size() : Renvoie le nombre d'éléments.
  • isEmpty() : Vérifie si la collection est vide.
  • get() : Pour récupérer un élément par son index (List).

4.5 Classes supplémentaires

  • Stack : Une pile (LIFO).
  • Vector : Similaire à ArrayList, mais synchronisé.
  • LinkedHashSet : Un Set qui maintient l’ordre d’insertion.
  • ConcurrentHashMap : Version thread-safe de HashMap.

5. Avantages et inconvénients des collections

5.1 Avantages

  • Dynamisme : Elles peuvent croître ou décroître en taille.
  • Fonctionnalités riches : Algorithmes prêts à l'emploi.
  • Flexibilité : Les collections sont dynamiques et peuvent croître ou décroître selon les besoins.
  • Richesse fonctionnelle : La JCF propose des algorithmes intégrés pour trier, rechercher, etc.
  • Interopérabilité : Les collections sont compatibles avec des API et frameworks tiers.

5.2 Inconvénients

  • Performance : Certaines opérations (tri, recherche) peuvent être coûteuses.
  • Complexité : Peut être déroutant pour les débutants.
  • Les collections ne permettent pas de définir directement des comportements spécifiques (contrairement aux classes).
  • La manipulation des types primitifs (int, char, etc.) nécessite un autoboxing, ce qui peut avoir un impact sur les performances.
  • Les collections sont plus complexes à utiliser que les tableaux pour les débutants.
