Exercice 8 : Calculatrice simple avec gestion des exceptions

1. Cours explicatif

Objectif : Apprendre à gérer les erreurs utilisateur (comme une division par zéro) et à écrire un programme robuste grâce à la gestion des exceptions.

Concepts abordés

  • Utilisation des blocs try-catch pour intercepter les erreurs.
  • Gestion des exceptions spécifiques comme ArithmeticException et InputMismatchException.
  • Validation des entrées utilisateur.

Exemple de division avec gestion d'une exception

import java.util.Scanner;

public class Exemple {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        try {
            System.out.print("Entrez le premier nombre : ");
            int a = scanner.nextInt();
            System.out.print("Entrez le second nombre : ");
            int b = scanner.nextInt();
            int resultat = a / b; // Peut provoquer une ArithmeticException
            System.out.println("Résultat : " + resultat);
        } catch (ArithmeticException e) {
            System.out.println("Erreur : Division par zéro.");
        } catch (InputMismatchException e) {
            System.out.println("Erreur : Entrée invalide.");
        } finally {
            scanner.close();
        }
    }
}

2. Énoncé

Écris une calculatrice simple en Java qui :

  1. Demande à l'utilisateur d'entrer deux nombres.
  2. Demande une opération parmi :
    • 1 : Addition
    • 2 : Soustraction
    • 3 : Multiplication
    • 4 : Division
  3. Affiche le résultat de l'opération.
  4. Gère les erreurs suivantes :
    • Division par zéro.
    • Entrées invalides (par exemple, si l'utilisateur entre une lettre au lieu d'un nombre).

3. Exemple attendu

Entrez le premier nombre : 10
Entrez le second nombre : 0
Choisissez une opération (1=Addition, 2=Soustraction, 3=Multiplication, 4=Division) : 4
Erreur : Division par zéro.

4. Conseils techniques

  • Utilise un bloc try-catch pour gérer les erreurs comme la division par zéro.
  • Utilise scanner.nextInt() pour lire les entrées et intercepte InputMismatchException pour valider les données.
  • Ajoute un bloc finally pour fermer le scanner.

5. Temps estimé pour un développeur expert

Environ 20 à 25 minutes.
